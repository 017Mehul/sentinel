# Security Policy

## Reporting a vulnerability

Please do **not** open a public issue for a suspected security vulnerability.

Use GitHub's private vulnerability reporting flow from the repository's **Security** tab ("Report a vulnerability") so maintainers can investigate privately. Include the affected commit or endpoint, reproducible steps, impact and prerequisites, and a suggested mitigation if known.

Do not include real user data, live credentials, production tokens, or third-party data in a report. Test only systems you own or have explicit permission to assess.

## Response expectations

The maintainer will acknowledge the report, triage severity, coordinate a fix, and agree on disclosure timing with the reporter. There is no guaranteed response or remediation SLA for this portfolio project.

## Supported versions

Only the latest state of the default branch is actively maintained. This project has not undergone an independent security audit.

## Scope and limitations

Sentinel is a portfolio-oriented IAM implementation. Its controls and automated checks are not a substitute for an independent penetration test, operational monitoring, incident response, managed-service hardening, backups, or a reviewed production deployment.
